# 网页 Cookie / Token 自动签到

支持库街区绑定的**国服鸣潮**角色。通过 GitHub Actions 定时运行，不需要桌面助手保持开启，也不需要 Java、Maven 或第三方 Python 包。

## 原项目实现与适配

原桌面版 `AutoSignService` 在启动时、次日 00:05 触发 `SignService.signAll()`，依赖本地账号数据库与常驻进程。原项目没有浏览器 Cookie 导入或云端签到入口。

实际鉴权使用 `token` 请求头，网页凭据对应 `source=h5`，App 凭据对应 `source=android`。来源不匹配也可能返回“登录已过期”，不能仅据此认定 Token 失效。`scripts/kurobbs_sign.py` 按现有 `KujiequRoleApi`、`KujiequSignApi`、`HttpRequestUtil` 和 `SignService` 的协议实现：

| 步骤 | 接口（均为 POST，参数放在 URL 查询串） |
| --- | --- |
| 查询绑定角色 | `/gamer/role/list?gameId=3` |
| 查询今日状态 | `/encourage/signIn/initSignInV2` |
| 提交签到 | `/encourage/signIn/v2`，增加北京时间的 `reqMonth` |

签到参数包括 `gameId=3`、`userId`、`roleId`、`serverId`。优先使用角色响应里的服务器 ID；未返回时沿用项目国服默认值 `76402e5b20be2c39f095a152090afddc`。

脚本自动处理每个账号下的全部绑定角色；先查状态，已签到则跳过；提交后再次查询确认。网络错误只自动重试查询请求（最多三次），签到提交超时后先查状态，不盲目重复提交。任一账号或角色失败会返回非零退出码，其他账号和角色继续执行。日志与 Actions 摘要仅含账号/角色序号和结果，不输出原始响应、Token、昵称或角色 ID。

## 获取网页凭据

1. 在自己浏览器中登录库街区网页，打开鸣潮角色或签到页面。
2. 按 F12 打开开发者工具的 **Network / 网络**，刷新页面，筛选 `api.kurobbs.com`。
3. 选择已成功的角色查询或签到相关请求，在 **Request Headers / 请求头**中复制 `token` 的值。如果有 `devcode`，也保留该值。
4. 若使用完整 Cookie，必须包含 `token=...`；脚本会提取并 URL 解码该字段。只有统计 Cookie、登录信息存在 Local Storage 的情况，请使用上一步的请求头 Token。不要将整段 cURL、响应 JSON、游戏启动器登录凭据当作 Token。

脚本默认使用网页来源 `h5`。如使用 App 来源 Token，必须按下面的步骤指定 `android`。凭据过期后需要重新登录对应客户端并更新 Secret，脚本不自动完成短信登录或验证码。

## 部署到 GitHub Actions

1. Fork 本仓库，确保 `.github/workflows/kurobbs-sign.yml` 位于 Fork 的**默认分支**。
2. 打开仓库 **Settings → Secrets and variables → Actions → New repository secret**。
3. 单账号创建 `KUROBBS_COOKIE`，值为请求头里的原始 Token，或者完整 `token=...; ...` Cookie。可另建 `KUROBBS_DEVCODE`，值为同一次网页请求中的 `devcode`；未提供时发送空值，与原项目的可空设备标识行为保持一致。
   如果是 App 来源凭据，在同一设置页面的 **Variables** 标签创建 Repository Variable `KUROBBS_SOURCE=android`；网页来源保持默认 `h5`。本地运行通过同名环境变量设置。该变量只作用于单账号配置。
4. 多账号改用 `KUROBBS_ACCOUNTS`，不要同时设置 `KUROBBS_COOKIE`。每个账号可单独填写 `source`，省略时默认为 `h5`。该 Secret 是 1 至 9 个账号的 JSON 数组，例如：

   ```json
   [
     {"token": "第一个账号的网页Token", "devcode": "对应网页设备标识"},
     {"cookie": "token=第二个账号的网页Token; devcode=对应网页设备标识"}
   ]
   ```

5. 打开 **Actions**，如 Fork 尚未启用工作流，先启用。选择 **库街区自动签到 → Run workflow**，保持 `verify_only` 未勾选，执行首次真实签到。
6. 查看运行的 **Summary** 和签到步骤。绿色结果才表示所有配置账号都已完成或当日已签到；离线验证模式跳过签到，不能证明凭据有效。

默认每天北京时间 **08:17、20:17** 执行，第二次用于补查，当日已签到不会重复提交。Cron 为 UTC `17 0,12 * * *`。手动勾选 `verify_only` 可以在没有凭据时验证 Python 环境和离线测试。

定时任务只在默认分支运行，可能受 GitHub 队列延迟影响；公开仓库连续 60 天没有活动时，定时工作流会被停用，需要重新启用。详见 [GitHub 定时事件说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。Fork 中工作流的启停方式见 [GitHub 工作流管理说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)。

凭据只存到 Actions Secrets，不放在代码、工作流 YAML、Issue 或运行输入中。工作流只有仓库读取权限，不提交保活记录。源码中的离线测试不使用真实账号；实际网页接口兼容性、网络可达性和凭据有效性以你自己的首次签到结果为准。

## 本地运行与验证

需要 Python 3.10+ 和系统时区数据；Actions 使用 Python 3.12 / Ubuntu。

```bash
# 只跑离线测试，不请求库街区
python3 -m unittest discover -s tests -p 'test_kurobbs_sign.py' -v

# Bash 隐藏输入，不把 Token 写进命令历史
read -rsp '网页 Cookie 或 Token: ' KUROBBS_COOKIE
export KUROBBS_COOKIE
python3 scripts/kurobbs_sign.py
unset KUROBBS_COOKIE
```

常见失败：

- **缺少凭据**：检查 Secret 名称，不能只配置 Repository Variables。
- **登录已过期 / 220**：先检查来源，网页 Token 使用 `h5`，App Token 使用 `android`；来源正确时重新登录对应客户端并替换 Secret。
- **没有绑定角色**：先在库街区绑定国服鸣潮角色。
- **HTTP 403 / 非 JSON / 业务失败**：在网页检查登录、设备标识及账号状态；云端出口可能被拦截，接口也可能变更。脚本不会将这类情况报为签到成功。
- **提交后未确认成功**：等待下一次补查或手动重跑，并对照网页当日签到状态。
